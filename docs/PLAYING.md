# Playing Dawngate yourself

Status 2026-10-09 (the match end and post-game since D8-live, the shop since D7b, the collection, store and loadouts in the main menu since B7b, the PvP queue since B10b, your progression after matches since B7c-live, the bots' missions and shopping since D6b, shaper select since D3-live, your perk pages in it since D3-perks, a second player since A5b, the shapers' passives and steadier bots since D6c, a headless match host since H1b, matches of any length since D1j, the other player in the match and the rejoin since G3, ability ranks and spawns checked on screen and the respawn voice line since D11, minion waves that spawn one by one and units that bump into each other since D1k, a party's match without a bot too many, leaving a match and a team that left surrendering since G3b, the jungle buffs and the Guardian's cores since D14 (the Guardian's shield, the cores, the towers' defence, crowd control, the parasite, fog details and the minimap checked live in D14b-live), the shapers' banter and kill lines since D11b, not yet checked live; your role's passive since D13-live; a frozen match that ends by itself and takes you back to the main menu since H5, checked live in H5-live; the jungle buffs, battle spells, recall and auto-attack, spirit wells under attack, leashing and deaths to NPCs checked live in D14a-live; only enemy shapers pause a well capture since D9c). You can log in to our server, start a **practice match** and play it: your shaper (Fenmore, or with `-ShaperSelect` the one you pick) on the full map, nine bots (four teammates, five opponents), minion waves, towers, creep camps, spirit wells and the two Guardians, run by our match host. Past your first practice match the PvP queue works too; with a second player on the same server (since A5b) the two of you can queue, form a party by name, chat in the lobby and get into one match, and since G3 you play that match together: you see each other, fight each other (or side by side), chat in it, and a player whose game closes can rejoin it. Everything stays on this PC (or, with the LAN setup, on your own network).

One command starts everything and cleans up afterwards:

```powershell
powershell -ExecutionPolicy Bypass -File re\scripts\play.ps1
```

Run it in a PowerShell window, from the repository folder (`<repo>`) or anywhere else. The sections below say what to set up once (one more command, `setup_all.py`), what to click, what works, and what to do when something goes wrong. To play against a server on another machine of your network, see *Playing on a server on another machine* below; running the server for others is [OPERATORS.md](OPERATORS.md).

**If something looks different from the original, tell us.** Our server had to guess some of the original's rules; a difference you can show (a video of the original game helps) is worth a report.

## One-time setup

You need:

- Windows 10 or 11, and the game files from archive.org: `Dawngate.zip` from <https://archive.org/details/Dawngate> (build 1.0.903.854).
- **Python 3.12**, **Go 1.24**, **Visual Studio 2022** (C++ desktop development with the x86 compiler; its bundled CMake is used), **Git for Windows** (its `openssl` makes the certificates) and the **RakNet 4.081** archive from GitHub (link and checksum in [OPERATORS.md](OPERATORS.md) *Setting up a machine*). Versions are in [SETUP.md](SETUP.md).
- **Wireshark with Npcap**, installed with "Support loopback traffic capture". It records each session so that the egress check can prove nothing left the PC ([SETUP.md](SETUP.md) *Wireshark and Npcap*). Without it, play with `-NoCapture` (below).

Put `Dawngate.zip` and the RakNet zip into the repository folder or leave them in your Downloads folder. Then, from the repository folder, two commands for the Python environment and one for everything else:

```powershell
python -m venv .venv
.venv\Scripts\pip install pefile cryptography
.venv\Scripts\python -I re\scripts\setup_all.py [--zip <Dawngate.zip>] [--raknet-zip <RakNet zip>]
```

`setup_all.py` extracts the game files into `client\ia_Dawngate` (never modified afterwards) and checks every file against the known build, makes our certificates, makes the client copy `client\run_854` and patches it so it talks to 127.0.0.1 only, builds the match host (`gms\`) and the server, makes the host copy `client\run_854_server` (a second copy of the game, 1.5 GB, with our match-host DLL), and builds the content file from your game files (what new accounts own; `--no-content` leaves it out, and new accounts then own no items). It prints a line per step and a summary; the first run took under two minutes on the development PC. Run it again whenever you like, and after every update of the repository: it skips what is current (a few seconds). `--check` only reports. What each step does, and the same steps by hand: [OPERATORS.md](OPERATORS.md) *Setting up a machine*.

Check the setup without starting the game:

```powershell
powershell -ExecutionPolicy Bypass -File re\scripts\play.ps1 -SetupOnly
```

`play.ps1` checks the same list at every start. It builds `gms\` again when its sources are newer than the DLL's last successful build (its build stamp `gms\build\Release\dgsim.dll.stamp`, G5), and it installs a new `dgsim.dll` into the host copy by itself. For anything else it prints the exact command to run. The server (`server\bin\dgserver.exe`) is rebuilt at every start; that takes about a second when nothing changed.

## Playing

```powershell
powershell -ExecutionPolicy Bypass -File re\scripts\play.ps1
```

**Or with two double-click files in the repository root** (since 2026-10-09): **Start-Server.cmd** checks and builds the setup like `play.ps1 -SetupOnly` and then runs the server in its own window, with shaper select (stop it with Ctrl+C or by closing the window); **Start-Client.cmd** then starts the game against it (it refuses while no server runs). After a match or a crash, start the client again without restarting the server. There is no capture and no egress check here (`play.ps1` has them). While the server window is open it holds lane a's session lock, so automated lane-a tests wait for it. `re\scripts\start_server.ps1 -NoShaperSelect` plays Fenmore without shaper select; `-ServerArgs '--owned starter'` passes server flags. Logs: `re\logs\manual_<date>-<time>\`. The client must be the patched copy `client\run_854` that `setup_all.py` makes: the original game talks to EA's servers (gone) and trusts only EA's certificates.

1. The game window opens after about 5 seconds (1440×810, windowed).
2. **Log in with any e-mail and password.** The first login with an e-mail creates that account. The password isn't checked, and the server writes it into its log in plain text, so use a made-up one.
3. **The first time, a news overlay appears** (three pages). Click its right arrow twice, then OK. It ignores Escape. Once you have closed it, it doesn't come back for that account: not when you return to the main menu after a match, and not at your next login (checked in B6-live).
   Behind it, the main menu's centre panel shows **our home page**: a welcome line with your name, a note that this is a restored community server, and buttons to the Collection, Profile, Leaderboard, Lore and Help screens. If the panel stays empty, your client copy's `Config_Pack.package` predates this page (`play.ps1` says so in a note): run `setup_all.py` again (*One-time setup*).
4. **PLAY, then PRACTICE DAWNGATE.** The server starts a match host ("Creating game, please wait."); the match loads after about 30 seconds. The match host is a second, headless `Dawngate.exe` (since H1b: no window, no graphics or sound, about 100 MB of memory, ready about 2 seconds after the click); you never see it.
5. Play. Right-click moves and attacks; Q, W, E and R cast your abilities at the cursor; Ctrl plus Q/W/E/R spends an ability point; B returns you to base; S stops.

**What works in a practice match today:**

- You play **Fenmore** on team 1 on the only map (`SM_Map_v5`), unless you start with **`play.ps1 -ShaperSelect`** (since D3-live): then shaper select opens after PRACTICE DAWNGATE, as in the original game.
  - **Select your Shaper:** the list shows every shaper your account owns (a new account owns all 37; testers can add a free rotation with the server's `--free-rotation`); your four bot teammates pick theirs within about 5 seconds, and their shapers turn grey for you. Click a shaper to see it, then its **Choose <name>** button (bottom right). The enemy team's picks stay hidden until the end (blind pick).
  - **Choose a Loadout and a Role:** pick one of your perk pages in **Choose your Loadout** (the drop-down lists the pages you saved in *Loadouts*, with what each gives; the first is preselected), click a role card (Gladiator, Tactician, Hunter, Predator; each lists its benefit), then **Finalize your selections!**. Since D3-perks the page counts in the match: its Spiritstones and Sparks raise your shaper's stats (e.g. +81.5 Health makes Fenmore's 450 HP 531.5), its Spiritstone's passive (e.g. *Adventurer*'s speed in tall grass) is on, and hovering the three-coloured perk icon in your shaper panel (bottom left, beside the role icon) shows the page's stats. Only complete Spiritstones count (every socket filled with a matching Spark); Sparks always count. The bots get a fixed bonus instead of a page (+9 Power, +108 Health, +4 Haste, +4 Armor).
  - **Choose a Skin:** click one of your shaper's skins below its picture (and a ward or announcer pack if you like); the phase ends after 15 seconds by itself.
  - Then every pick is revealed and the match loads with your shaper in the skin you chose. A practice game gives you 5 minutes for each of the first two phases; when you don't pick in time, the server picks for you (the first free shaper of your list, the role you had). The game saves your skin and perk page for that shaper on your account at the match start and preselects the skin next time (checked in D3-perks). The **?** card at the end of the list (scroll down) picks a random free shaper when you choose it.
  - Checked live in D3-live (sessions `d3live_run4`–`d3live_run6`: Petrus by the timer, Amarynth picked by clicks, Amarynth in her *Moonrise* skin, all played by the host) and D3-perks (`d3perks_run1`–`d3perks_run3`: a perk page chosen, its stats in the match, the random card).
  - Your perk pages need a content file built since D3-perks (`setup_all.py` rebuilds an older one; the server's start line says "no perk stats" otherwise): with an older one the pages are listed and chosen, but give nothing in the match.
- **Bots (since D6a):** the practice match is five against five: four bot teammates (High Huntress, Guardian, Artist, Warden) and five bot opponents (High Huntress, Tidal Queen, Guardian, Artist, Warden). They wait in their bases until about 1:05, then take their lanes (two top, three bottom), last-hit minions, cast their abilities, push towers, fight you and each other, level up, die and respawn; their kills, deaths and assists count on the scoreboard. Since the practice match is a first-time game, the bots go easier on you (the game's own FTUE rules). `-HostOptions 'bots=0'` turns them off, `bots=N` fills N seats a team.
  - **Shopping (since D6b):** whenever a bot is at its base (after leaving it at 1:05, on its way back and after a death) it buys the next step of its shaper's recommended build (the shop's *Recommended Items*: a starting item, then the components and upgrades of its core items) and keeps two potions; you see your teammates' items, gold and potions in their inventories, and they drink the potions when hurt. In a 13-minute test the nine bots bought 23 items and 43 potions (14,720 gold).
  - **Since D6c** the bots finish their spells instead of cancelling them with the next one, run out of a Guardian's or the parasite's area attacks (the "fire" on the ground) before it hits, no longer flick back and forth between chasing an enemy and walking back to their lane, and capture your team's spirit wells when nobody defends them (seen twice in a 13-minute test).
  - **Wards (since D6d):** when a bot wants to ward, it walks to the ward spot (a bush, a well, a tower's flank: 18 fixed spots, the nearest on its side of the map) and places its ward there, about 16 units short of the spot. Before D6d a bot whose spot was out of reach stood still, sometimes for the rest of the match (High Huntress bots most often); since D6d no bot stood still for three minutes in two 30-minute matches.
  - **Missions (since D6b):** the bots also play as a team: they come to help defend a tower that an enemy attacks, go for a spirit well of the other team once it can be captured (and defend their own well when an enemy stands in it), gather to fight the parasite (and to contest it) and join an ally that goes in for a kill. With `wells_lock_first=45` the enemy bots attacked your team's well after about 10 minutes, your team got the "under attack" warning, and your bots came to defend it. (Since D9b that warning, a voice line and a minimap ping at the well, is the game's own and comes when an enemy hits one of the well's workers; a capture alone shows in the well's ring and the score panel.)
- Moving, basic attacks (walking up to the target), abilities, ranking them up, returning to base.
- **A move takes over an attack at once (since D7c):** one right-click on the ground stops a basic attack, its walk-up and an attack-move (A + click) that has started fighting, and your shaper walks off at once. Before D7c the first click after such an attack-move was carried out only after the walk-up and the first hit (a second click or S freed the shaper; with *Enable Auto Attacks* off only the wind-up was cut short): that was the original game's own server code, which our match host now overrides. A move still waits while one of your abilities holds you in its cast (e.g. Kensu's Q, about half a second), as in the original; S stops at once. A new attack-move during a fight keeps fighting first. Testers: `-HostOptions 'move_takeover=0'` brings back the original's rule.
- **Ability ranks (checked in D11):** every level gives you an ability point (except level 10, which gives a spell point instead), and Ctrl plus Q/W/E/R spends it. Q, W and E go up to rank 5, one more rank every two levels (rank 2 from level 3, rank 3 from level 5, rank 4 from level 7, rank 5 from level 9); your ultimate R goes up to rank 3, at levels 6, 11 and 16. A rank-up past those limits is refused, as in the original game, and the yellow **+** above an icon shows only where a rank-up is allowed. The small bars under each ability icon count its ranks (three wider ones for R), and hovering an icon shows the values of its current rank. Each rank does what the game defines, e.g. Fenmore's Q (Soul Rend) deals 65, 115, 165, 215 and 265 damage with a cooldown of 11, 9.5, 8, 6.5 and 5 seconds. The bots rank their abilities as they level up, their ultimates at 6, 11 and 16 too. A level-up shows "LEVEL UP!" and a ring around your shaper.
- **Units bump into each other (since D1k):** minions, creeps, workers, bots and your shaper no longer walk through each other; they collide and push each other slightly, as in the original (the item *Fluidity* lets you pass through units). If your shaper seems blocked by a line of minions, walk around it.
- **Spawning (checked in D11):** your shaper starts in the base, minion waves appear at their spawn wells and jungle creeps at their camps without a spawn animation or effect: this version of the game has none in its data (only the Guardians, the parasite and some pets have spawn animations of their own, which their scripts play). When you respawn, your shaper speaks its respawn line (the game's own voice line; not checked by ear yet).
- **What you see of attacks and abilities (checked on screenshots in D10):** every cast plays its animation and effects, and every projectile flies as the game draws it. Fenmore's basic attack is a blue bolt from his glowing hands; Q (Soul Tear) a purple tether to the target and a shield on you; W (Stim) red glowing hands and a buff icon; E (Heart Eater) a spectral wolf leaping out along your aim and back, with a paw marker behind you; R (Ravenous Pack) the cast bar and wolves circling you. Towers shoot a bright beam from their crystal, ranged minions blue (yours) or orange (enemy) fireballs, melee minions and melee shapers strike with hit flashes, and the bots' abilities show too (Tidal Queen's water bubble and ground rings, High Huntress's bolts). Damage, gold and XP numbers pop up, health bars drop. Before D10 a match host could stop every ability and projectile for the rest of the match after Fenmore's E (the host's Lua stopped after an internal error); if you saw abilities stop working in a match, that was it, and it is fixed.
- **Minion waves** start at 1:00 and come every 30 seconds. **Since D1k** a wave's six minions appear one after another at their spawn well, half a second apart (three melee, then three casters), and walk their lane in a line, as in the original game. They walk their lanes and fight each other and the towers. Where a lane's Bindings are down, the minions walk into the enemy base and attack its cores (the nubs) and the Guardian, nearest first; minions alone can destroy the Guardian and win the match (since D5). **Since D14** (checked live in D14b-live) the Guardian is invincible, with a blue shield effect around it, as long as any of its five cores stands, as the game's own tip says: destroy the cores first. A destroyed core makes the other team's minions stronger (+30 health and +2 Power for melee, +15 and +4 for casters) and regrows after eight minutes, and the shield comes back with it. Lanes fall tower by tower, outer first: in every long test match the minions and bots took a lane's Bindings in order before the base. A tower shoots minions before shapers, but switches to an enemy shaper who hurts you near it and stays on it; its beam shows whom it targets. Inside the enemy base the Locus (the big tower) destroys intruders.
- **Long matches (since D1j):** a match runs as long as it lasts. Until D1j the match host ran out of room for the units' abilities after about 13 minutes (every dead minion kept its share), and waves spawned later fought badly; checked with a 32-minute match against the bots, minions still fighting at the end. The soak test (Q3) played four half-hour matches the way a player would (walking a lane, fighting, shopping, capturing a well, with and without shaper select): the match host's memory, speed and network traffic stayed the same from start to end, nothing you see drifted from what the host has, and a win after 30 minutes ended with the usual post-game and rewards. The bots alone rarely finish a match: even with one lane's towers gone, the minions didn't bring a Guardian down in 12 minutes, so push yourself. Sometimes a High Huntress bot stands still for a long time (it wants to place a ward out of its reach; D6d).
- **Towers (Bindings), the Guardians, creep camps and the parasite** fight. Camps respawn after you clear them.
- **Jungle buffs (since D14, checked live in D14a-live):** killing a buff camp's big creature (the Fish, Fungus or Ugger major) gives the last hitter its buff for 150 seconds: Green +15 Power and +10 %, Blue +20 Haste and another +20 for 3 seconds after each ability, Orange +20 armor and a 1 % damage reduction stack for each hit you deal (3 seconds). The buffs show as icons above your ability bar with their time left, and a coloured ring around your shaper; a second kill of the same buff renews it to 150 seconds (the bonus doesn't double), and you lose them when you die. A creature killed by a minion gives nobody a buff. Until D14 nobody ever got a jungle buff. The big creature stands at its camp's marked spot (the one the tutorial pings). Killing the parasite at its second or third stage gives your whole team its buff.
- **Battle spells (checked live in D14a-live):** you choose your spells in the match: click **SPELL BOOK** under the spell slots (next to your abilities), pick one of the twelve spells (Offense, Defense, Utility) and confirm. You can learn a spell only at your base ("Out of range of Locus" elsewhere); you get one spell point at level 1, the second at 10 and the third at 20. Use a spell with the item keys 1–3. Each spell does what the game defines (e.g. Exceed: +30 Power and 30 % more for 5 seconds; Blink: a teleport up to about 18 units; Vanquish: 300 + 30 per level true damage to a minion, creep or well worker, not to shapers or structures); its cooldown shows on the slot, keeps running while you are dead and stays with the spell when you swap it to another slot. Recall (B) is cancelled by a hit, a move, a stop or an attack. After a move your shaper attacks an enemy in range by itself (also creeps and workers that are fighting you); after **S** (stop) it doesn't until your next command.
- **Checked live in D14b-live:** the parasite (the creature in the middle of the map, an untargetable egg until 5:00) ignores you until you hit it, then attacks only you and stops when you walk away (beyond about 27 units), heals to full when nobody fights it, and hides in fog like other creatures. Killing it pays your team (150 gold at its first stage, 350 at its third); after a third-stage kill your team gets its big buff for 3 minutes and your lanes get a large Strider in every wave for 4 minutes (in the test those waves alone took all of the enemy's towers). It comes back 5 minutes after its death. Crowd control works as in the game: knock-ups throw minions up and they walk on, stuns end on time, a move you give while stunned is carried out when the stun ends, you can buy items while dead, and you can move at once after respawning. With the item *Fluidity* your shaper walks straight through a line of units. Jungle camps show the health they really have when you see them again after fog, a projectile flying out of the fog appears mid-flight, and a heal shows its green number even when the healer died. Tall grass hides you from minions that were attacking you. Not checked yet: the dead ally's skull and the recall spinner on the minimap, a stage-up that was due while the parasite was dead.
- **Fog of war (since D2g-live):** enemy minions, jungle creeps and the parasite are hidden while none of your team's units (your shaper, your minions, your towers, your wards) sees them, and appear when one does; the map is lit around your team's units and darker elsewhere, and the minimap shows only what your team sees. Towers, the Guardians, shops and gold piles are always visible. The enemy's units don't see you through fog either. `-HostOptions 'fog=0'` turns it off (everything visible, as before).
  - **Walls and tall grass block vision (since D2g-rest),** as the game draws it: you don't see behind a wall, and you see into a grass patch, or past it, only from inside that patch. Standing in grass, you are hidden from enemies outside it (your shaper turns half transparent and the game shows its "Tall Grass" tip), until you use an ability there: that reveals you for a second. A ward (the ward key) placed in a patch lets your team see into it; it becomes invisible to the enemy 3 seconds after you place it.
  - **Stealth hides (since D2g-rest):** a stealthed enemy (Weaver's Q, a ward, a trap) stays hidden even right next to you; your own stealthed shaper is drawn half transparent. Nothing in this version of the game detects stealth.
  - **Chasing into fog (since D2g-pursuit):** if the target you are walking up to (to attack it or to cast at it) disappears into fog or tall grass, your shaper walks to where your team saw it last and stops there; if the target shows up again on the way, your shaper follows it and attacks or casts. Minions and bots chase the same way (checked in two 13-minute matches with bots): when you slip into grass they head for where they lost you, no longer for the middle of the map.
  - **Enemy shapers' levels and items (since D2h):** an enemy shaper's health bar, the target panel and the scoreboard (Tab) show its real level, items, creeps and gold while your team sees it; when it comes out of the fog you see its current level at once (a level it gained out of sight included), and while it is out of sight the scoreboard keeps what you saw last. Before D2h every enemy, bots included, showed level 1 and no items for the whole match. `-HostOptions 'fow_data_by_vision=0'` brings the old behaviour back.
  - Testers can switch the walls, the grass and stealth off one by one: `-HostOptions 'fog_terrain=0'`, `'fog_grass=0'`, `'fog_stealth=0'` (and `'fog_pursuit=0'` brings back the old walk to the map's middle).
- **Shaper passives (since D6c):** every shaper's passive ability runs, yours (Fenmore's *Conversion*) and the bots', from the start and again after each respawn; before D6c no passive worked in our matches. What each passive shows on screen hasn't been checked one by one yet.
- **Role passives (since D13-live, checked in the server's logs):** your role's bonus runs too, from the start and after each respawn. **Gladiator** (melee shapers only): minions dying near you that you didn't kill store extra gold, paid with your next minion last hit (+1 creep score for every two stored); **Hunter**: +10 % damage to jungle creeps, a heal of 2.5 % of a creep's health when you kill it, and a quarter of creep kills pay +30 gold; **Predator**: double gold from well workers; **Tactician**: +20 gold for hitting an enemy shaper, at most once every 5 seconds per kind of attack (melee or ranged). Without shaper select you are a Gladiator; the bots' roles come with their shaper. Testers can switch them off with `-HostOptions 'role_passives=0'`.
- **Damage and death** follow the game's own rules (armor and magic resistance, crits, shields, lifedrain). A projectile already on its way still hits when its caster dies (since D6c). Last hits and kills give gold and XP, and you level up. You start with 500 gold and get 100 gold a minute from 1:00.
- **Spirit wells (since D9):** each team starts with two wells. Workers appear at your wells (one every 15 seconds, up to 18 per well) and walk between their spots and the well; every worker adds 1.5 gold a minute for each player of the owning team, paid every second. The score panel at the top shows each team's well gold per minute. From 15:00 an enemy well can be captured: stand in its central ring for 16 seconds (the ring fills). **Since D9c** only enemy shapers can stop it: a hit from an enemy shaper (a player or a bot, or a shaper's pet) pauses your capture for 5 seconds, and an enemy shaper standing in the ring holds it as long as it stays; workers, minions, creeps, towers and your own abilities' health costs no longer pause it, so you can capture while the well's workers and minions hit you (checked in D9c: 56 such hits, the capture in 16 seconds). Before D9c any damage paused it (a capture could take three times as long; testers can bring that back with `-HostOptions 'wells_damage_pause_any=1'`). A capture turns the well to your colour, destroys its workers, pays every player of your team 50 gold plus the well's bounty, and locks the well for 4 minutes (the lock ring runs down); then your own workers start gathering there. Killing an enemy worker lowers that team's income until the worker is replaced (15 seconds later) and pays you 6 gold and 15 XP if you are within about 16 units of it (from farther, e.g. a Vanquish at its full range, nothing; checked in D14a-live). A worker you hit fights back but never flees; it gives up on you once you are out of its reach and goes back to work; a root holds a worker in place, and when it ends the worker jumps ahead to where its work cycle is. When an enemy hits one of your workers, the game raises its "well under attack" alert (the well's icon in the top bar shows a yellow "!"); while an enemy captures your well you see the ring fill in their colour, then "An Ally Spirit Well has been captured" (checked in D14a-live). Testers can unlock the wells earlier with `-HostOptions 'wells_lock_first=45'`.
- **Your death:** the screen turns grey, your portrait counts the seconds to your respawn (about 16 at the start), "View Death Recap" opens the recap, and you come back at your base with full health (seen on screenshots in V1-live). The announcer names your killer's kind: "A Minion has slain …" for a creep or the parasite, "The Guardian has slain …", "A Binding has slain …", or the enemy shaper who hit you last; the recap labels the source (Creature, Parasite, Guardian, Binding, a shaper's name) and an NPC's kill pays nobody (checked in D14a-live). The recap button toggles the panel ("Hide Death Recap"); a panel left open keeps showing the recap it opened with until you close and reopen it.
- **Buffs:** a potion's buff shows as an icon above the ability bar with its time left, and the icon goes when it ends (V1-live).
- **The shop (since D7b):** buy and sell items while you stand in your base (within about 40 units of its centre) or while you are dead. The gold goes down, the item appears in your inventory and its stats apply at once (`Basic_Life`: +100 health, +5 health regeneration); stacks of potions grow in the consumable slots, and selling pays half the price back. A purchase you can't afford, or one away from your base, is refused. Open the shop with P, click an item (or one of the recommended "Starting Items" at the top), then **Purchase** at the bottom right; an item you can't afford says "Insufficient funds for purchase." (checked live in V1-live: two potions bought by clicks, gold 500 → 460 → 420, the stack in the shop's inventory and on the HUD). Your items keep their passive effects when you die (since Q3; before, an item such as *Hunger* lost its healing effect at your first death for the rest of the match, and upgrading it later logged an error).
- **Potions:** drink a healing potion with its item key (4 or 5) when you are hurt (checked live with key 4); at full health the game itself refuses it, and standing in your base heals you anyway.

### The PvP queue (since B10b)

On the VERSUS tab, **QUEUE SOLO** puts you into the PvP queue: the PLAY button reads "MATCHMAKING..", a timer counts up, and the tile becomes CANCEL MATCHMAKING, which takes you out again at once. The server waits 15 seconds for other players; since nobody else is on it, it then gives you a match of your own ("Starting Game — Waiting for all players to connect.", then the loading screen, about 25 seconds in all). **Since B10d the empty seats get bots:** like a practice match, you play with four bot teammates (High Huntress, Guardian, Artist, Warden) against five bots (High Huntress, Tidal Queen, Guardian, Artist, Warden), who leave their bases after about a minute, take their lanes, shop and fight (checked in B10d, lane b: all ten players on the client, the allies' portraits in the team panel). Unlike a practice match the bots don't go easier on you: a PvP match isn't a first-time game. The server's operator can leave the seats empty instead (`dgserver --mm-bots=false`, [OPERATORS.md](OPERATORS.md)); then it is just you, the minion waves, towers, camps and the enemy Guardian (as in B10b). A PvP match doesn't count as your first practice win.

**The end of a PvP match (since D8b, checked with two players):** after the victory or defeat cinematic comes **Karma Voting**: both teams' players are listed (your team first), and the green button at the right of a row gives that player karma ("Vote for players you want to receive Karma!"; your own row has none). The bar under the text counts down 20 seconds; your votes are sent when it runs out. Then **Blessings** shows how your loot bag was earned: the base roll, the victory bonus and game duration, the first win of the day and **Karma Bonus** (+10 for every vote you got; the server counts it into your bag). Click **Continue** for the loot bag, then the bag to open it; if you don't, the server ends the match about 105 seconds after the end and you are back in the main menu.

**Surrender (since D8b; PvP and custom matches, not practice):** from **20 minutes** into the match, open the Options menu with the **gear icon** above the minimap (Escape doesn't open it) and click **SURRENDER GAME** (greyed out before that), or type **`/surrender`** in the game chat (Shift+Enter). That starts your team's vote with your own yes. Your teammates see a **Surrender** window at the right with the vote and **Yes**/**No** buttons (or type `/surrender` / `/nosurrender`). The vote passes with two thirds of the team (the game says "requires 66%"): 1 of 1, 2 of 2 or 3, 3 of 4, 4 of 5; it fails as soon as that can't be reached any more, or after 60 seconds with the missing votes counted as no. A pass ends the match at once: "The surrender vote has passed!" for your team, "The Enemy team has surrendered!" and the victory for the other, then the karma vote as above. After a failed vote your team must wait 5 minutes ("Surrender unavailable due to recent failed surrender vote"); before 20 minutes the game says "Surrender is not yet available this match". Bots don't vote. A team can also surrender earlier when a player has been disconnected for 5 minutes ("Surrender is now available due to a player being disconnected too long", seen in G3b), or when it is 19 kills or 20,000 gold behind (these rules are our assumptions; the last two haven't been seen in a match yet). Testers can make surrender available earlier with `-HostOptions 'surrender_after_s=20'`.

**CUSTOM (since B15; built and unit-tested, not yet tried in the game, so expect rough edges):** **CREATE GAME** asks for a game name (and an optional password, which makes the game private) and opens the custom lobby with you as its owner: two teams of five and five spectator slots. Another player finds the game under **BROWSE GAMES** (name, owner, players, spectators, map, region; a padlock for a private game), selects it and clicks **JOIN GAME** (or **SPECTATE GAME**). In the lobby a player can **Join Team** to switch sides, the owner can move and kick players (right-click a slot) and clicks **START** when the teams are set; then everyone goes through the loading screen into the match together (shaper select first when the server runs with `--shaper-select`). The open seats stay empty unless the server runs with `--custom-bots`. If the owner leaves the lobby before the start, the game is closed. **Spectating (since B15b; built and unit-tested, not yet tried in the game):** a spectator (SPECTATE GAME, or Join Team on the spectator slots) goes through the loading screen with the players (seeing both teams' picks in shaper select) and then watches the match in the game's spectator view: what either team sees (the view can switch to one team's sight or to everything), no shaper of its own, no shop or abilities, no surrender or karma vote, no rewards; SPECTATE GAME also works on a match that has started. An owner on the spectator slots with `--custom-bots` watches a game of ten bots. Not tried yet: the Europe region and "Match With All Regions". The server's queue rules (team size, the 15-second wait, a limit on the wait) are `dgserver` options ([OPERATORS.md](OPERATORS.md)); `play.ps1` uses the defaults.

### Playing with a second player (since A5b)

Two game clients can log in to one server at the same time, each with its own account (checked on one PC with two client copies, A5b; on two machines see *Playing on a server on another machine* below). What works:

- **Both in the PvP queue:** each clicks QUEUE SOLO. With the server's team size 1 (`dgserver --mm-team-size 1 --mm-min-players 2`) the two get one match against each other at once; with the defaults (5 a side, a 15-second wait) also, after the wait.
- **A party:** the leader clicks **CREATE A GROUP** (the *Versus Group Lobby*), then the add-players icon below the team list. In **"Invite players to game"** type the other player's **name** (the name shown at the top right of their main menu) into the field at the top left and click the small person-plus icon next to it; the player appears in the list as *Pending*. The list below shows your friends, else it stays empty (since B13b the server keeps friends; making one in the chat, by a friend request the other player accepts, isn't checked live yet: B13b-live); close the dialog with its X. The other player gets a **"Matchmaking Invite"** pop-up at the bottom right ("… has sent you a game invite. Do you accept?"): **YES** puts them into the leader's lobby.
- **The lobby chat** on the right: type a line and press Enter; both see "[Lobby] [name]: text".
- **Each member's card shows its wins** (since B14, not checked live yet; before, the invited player saw the leader's wins as 0), and the new wins after a match together.
- **QUEUE AS GROUP** (leader only) queues the party together; both land on the same team in one match.

**In the match (since G3):** both players are in it as themselves: each client has the other player (name, team, shaper, kills and deaths, the death timer), the other's shaper shows up as soon as your team sees it (fog of war), and kills between the two count as player kills (the killer's score, the victim's death recap). The loading screen waits until both clients have loaded. In the solo queue with team size 1 you play against each other (that is what G3 checked); with a party both are on the same team (D8b played surrender votes in one). Open seats are filled with bots as usual. How the match ends with the karma vote, and how to surrender: *The PvP queue* above.

**If your game crashes or you close it during a match**, your shaper stays in the match (standing where it was, as if away), and the other player's client shows you as gone. Start the game again and log in with the same account: the main menu shows **"Disconnect Detected! Your match is still in progress"**; click **Rejoin** and you are back in the same match, on your team, with your shaper, score and gold (Quit gives the match up). This works while the match runs and the server is the same one (a restarted server forgets running matches, and its match hosts end with it).

**Leaving a match on purpose (since G3b):** the gear icon's **LEAVE CURRENT MATCH** asks "Leave Match? … You won't be able to play another match until this one completes." **YES** takes you back to the main menu at once, which then offers the same **Rejoin** as after a crash (the game keeps a left match open for you); your shaper stays in the match as for a crash. **When every player of a team has left** (closed, crashed or left) and stays away for **60 seconds** while the other team still has a player, that team surrenders: the others see "The Enemy team has surrendered!", the **VICTORY** and the karma vote (G3b; PvP and custom matches; our rule, from the community's description of the original).

**The match-found prompt (testers, since G3b):** with `-HostOptions 'prepare_flags=1'` a PvP match first shows **"Match Found — Click 'accept' to join."** with **ACCEPT**/**DECLINE** and a 20-second bar, the original's dialog; the match starts once everybody accepted. A **DECLINE**, or nobody clicking within the time, cancels the match for everyone: the players who accepted go back into the queue by themselves (the timer keeps counting), the one who declined to the play screen. `play.ps1` doesn't turn it on (the default accepts by itself).

**Chat in the match:** press **Shift+Enter** (it opens the game chat: "Switched to game"; Enter alone didn't open it in our tests), type your line and press Enter; the other player's client gets it (both are in the match's chat channel on the server). Not yet: whispers. The block-list asserts the clients logged before ("Race condition : Checking block list before its loaded!") are gone since B13 (no assert on either client in G3's two-client matches).

Each PRACTICE starts a new match host. Several matches in one session work (checked with two in a row in D8-live; their logs go to `host\1`, `host\2`, …).

## Stopping

- **Quit the game**: close its window at the login screen or in the main menu. In a match the close button doesn't work (the game ignores it there), so use Ctrl+C.
- **Or press Ctrl+C in the PowerShell window.** It closes the game; in a match it stops the game after 10 seconds. Pressing Ctrl+C a second time stops at once.

Either way, the script then waits up to 20 seconds for the match host to end, stops the server and the capture, runs the egress check and prints a summary:

```
==== Dawngate session play_20261008-160000 over: OK
  session : ended when the game was closed at t=1230 s (code 0) after 21 min
  egress  : 0 flagged line(s) (egress.txt)
  cleanup : 0 leftover(s) stopped before the run; stopped after it: dgserver.exe x1, dumpcap.exe x1; ports free, no session process left
  logs    : <repo>\re\logs\play_20261008-160000
```

- **egress** must say `0 flagged line(s)`. If it says `EGRESS FLAGGED` (exit code 1), something tried to leave the PC. Stop playing, keep the folder and report it (`egress.txt` lists the lines).
- **cleanup** must end in `ports free, no session process left`.

Wait for the summary before you close the PowerShell window. If you close the window early, the game or the capture may keep running; the next start of `play.ps1` stops them.

A session ends after 8 hours at the latest: that is the safety limit of the server and the capture. `-Seconds N` ends a session after N seconds.

## Where the logs go

Everything of a session is in `re\logs\play_<date>-<time>\` (gitignored, never committed):

| File | What |
|---|---|
| `summary.txt` | the full summary: game states, Blaze requests, the match host, egress, cleanup |
| `application_log.txt` | the client's log for this session (its full log is `%APPDATA%\DawngateData\Application.log`) |
| `stub.log` | the server's log: logins, every request, the match host's control messages, telemetry |
| `host\<n>\dgsim.log` | match *n*'s host: the simulation, the GMS session, replication, deaths and the match end |
| `host\<n>\stdout.txt`, `host\<n>\AppData\` | the host's console output and its own game folders |
| `host\<n>\watchdog.txt`, `host\<n>\watchdog.dmp` | only after a frozen match (since H5): where the host hung, its last log lines, and a minidump (`re\scripts\minidump_stack.py` reads it, since H5-live with the DLL frames named) |
| `host\<n>\host_timing.csv` | since Q3c: one row per match minute: how long the host's ticks took, what it sent, how fast it answered your commands, its records (`.venv\Scripts\python -I re\scripts\soak.py timing re\logs\<session>` makes a table of it) |
| `session.log`, `monitor.log` | what the script and the monitor did |
| `capture.pcapng`, `egress.txt` | the capture (256 bytes per packet, enough for the check) and the egress check's report |

Accounts are kept in `server\data\accounts.json`.

## Troubleshooting

- **"another session is running"** (exit 2): only one session can run at a time, whether a play session or an automated test session. They use the same ports, and a new session would otherwise stop the running one's processes as leftovers. Every session writes `re\logs\session.lock` and removes it at the end. Wait until the other session has ended. Delete the lock only if no `run_session.ps1` or `play.ps1` is running any more.
- **Leftover processes** (after a crash or a closed PowerShell window): the next start stops them, and only our own: `dgserver.exe` from `server\bin\`, `Dawngate.exe` and `CrashSender1402.exe` from `client\`, the monitor, and `dumpcap` writing into `re\logs\`. To look: `Get-Process Dawngate, dgserver, dumpcap -ErrorAction SilentlyContinue`.
- **"ports held by other programs"**: another program holds one of our ports: TCP 42127, 10041, 17502, 18080, 9988 and 10040, UDP 17502 and 10042–10051. Find it with `Get-NetTCPConnection -State Listen -LocalPort 42127,10041,17502,18080,9988,10040` or `Get-NetUDPEndpoint -LocalPort 10042`, and close it. The script never stops programs that aren't ours.
- **The game closes right away, or `play.ps1` says another Dawngate.exe is running:** only one Dawngate client can run at a time (the game's single-instance mutex `Global\Dawngate`). Close the other one. The match host is the exception: it runs with `-multipleInstances` next to your client.
- **Separate AppData:** your client keeps its log and options in `%APPDATA%\DawngateData` (`Application.log`, `Preferences\Preferences.prop`). The match host is a second `Dawngate.exe` and keeps its own folders under `re\logs\…\host\<n>\AppData`, so the two never write the same files. The automated test sessions use the same `%APPDATA%\DawngateData` as you. If you switch to fullscreen or change the resolution, the tests run that way too, and they expect the default 1440×810 window. Switch back to windowed before running test sessions (or delete `Preferences.prop`, which resets every option).
- **The login screen says it can't connect, or stays at "Initializing":** the certificates and the patched exe must match. `play.ps1` checks that; after new certificates, run `patch_client.py` again (*One-time setup*). Otherwise read `stub.log`.
- **Nothing happens after PRACTICE, and the envelope at the bottom right shows "1":** the server couldn't start a match host. Click the envelope, then the "Notification" entry: it says "Game creation failed - no servers available" (a notification, not a pop-up; seen in V1-live). Read the `[host]` lines in `stub.log` (the host copy, its `dgsim.dll`).
- **"Failed to connect to game server" about 20 seconds after PRACTICE:** the host ended before it was ready. Read `host\<n>\dgsim.log`.
- **The world freezes in a match** (nothing moves; your shaper still walks, but can't attack or cast): since H5 the match host notices a stalled server tick after about 10 seconds and ends the match; you are back at the main menu without a message, as after a host crash, and PRACTICE starts a new match. The host leaves `host\<n>\watchdog.txt` (where it hung and its last log lines) and `watchdog.dmp`; keep them with the session folder for a report. Checked live in H5-live (2026-10-09, with a test stall): the client was back at the main menu's home page about 10 seconds after the world stopped, with no dialog, and PLAY → PRACTICE DAWNGATE started the next match normally. A server error that hits only one part of a moment (one skipped step) no longer freezes anything: the match goes on; one that repeats for 10 seconds ends the match the same way.
- **Something in a match works differently from what this page says, and you wonder whether the headless match host is the cause** (since H1b the host skips the game's graphics, sound and menus; everything on this page was checked with it): start with `play.ps1 -HostOptions 'core_only=0'`. The host then starts the way it did before H1b (the full game hidden in the background: about 1 GB of memory instead of 100 MB, ready after 5–8 seconds). If that fixes it, report it with both session folders.
- **A Windows Firewall prompt** for `dgserver.exe` or a `Dawngate.exe`: everything listens on 127.0.0.1 only, so you can cancel it.
- **The game crashed:** CrashRpt's window may appear. Its report stays on this PC (it is never sent) under `%LOCALAPPDATA%\CrashRpt\UnsentCrashReports\` and contains screenshots of every monitor; delete it if you like. The summary's `game` line then says `CRASH SENDER RAN`.
- **"running scripts is disabled on this system":** start it as shown, with `powershell -ExecutionPolicy Bypass -File …`.

| `-Seconds N` | end the session after N seconds |
| `-Name <name>` | the logs folder's name (default `play_<date>-<time>`) |
| `-HostOptions 'key=value;…'` | settings for the match host (the host's `[host]` keys, e.g. `test_wave=20`, or `core_only=0` for the pre-H1b full start-up, *Troubleshooting*); for testing |
| `-ShaperSelect` | shaper select before the match (D3-live): pick any shaper your account owns, a role and a skin (below); without it you play Fenmore |
| `-KeepAlive` | keeps the idle kick away: every 60 seconds the script sends the game window a harmless key release (F24, a key standard keyboards don't have). It never touches your keyboard or mouse. Off by default (B12; checked live: a test session stayed in its match for 6 minutes on it alone) |
| `-SetupOnly` | check (and build) the setup, don't start |
| `-Check` | the non-interactive check (below) |
| `-Server <S>` | play on the server at `<S>` on another machine of your network with the lan copy (next section); no local server or match host. With it, `-AllowHost <H>` adds the operator's match-host machines to the egress check |

## Playing on a server on another machine

**Checked on one PC, not yet across two** (A5b: the development PC played server and player at once on its own LAN address, to the main menu and into a practice match, with nothing leaving the PC; a real second machine needs a VM, H3-live). The patches, the setup command and the server's address handling are built and tested offline (A5a, H3-offline). A match is what *Playing* above describes: a practice match of your own, or the PvP queue and parties of *Playing with a second player*, together with the other players in the match (G3). **The start command `play.ps1 -Server <S>`** (P2, below) is tested without a game (its dry runs, `re\scripts\test_p2.ps1`) and, since P2-live (2026-10-09), live on the development PC: its `play_lan.ps1` played the lan test copy against a server on the PC's own LAN address, logged in, went into a practice match on that server's match host, was closed by the time limit and by a Ctrl+C, and ended with 0 flagged egress lines and nothing left running (*The check mode* below).

**Copies made before A5b with `--client-bind`** couldn't connect to a match (the game's network test failed; fixed in A5b): run your `setup_all.py --player …` command again, which patches the copy anew.

From the server's operator ([OPERATORS.md](OPERATORS.md) *Running the server*) you need two things: the server's LAN address `<S>`, and the file `ca_modulus.bin` of the server's LAN certificates (`server\certs\lan\ca_modulus.bin` there, made with `setup_all.py --lan-certs <S>`). It is the public part of the server's certificate authority: no key, no password.

On your machine you need the repository, `Dawngate.zip` and the Python environment (the two `.venv` commands under *One-time setup*), and, for the capture and the egress check that prove nothing but the server is contacted, **Wireshark with Npcap** (as under *One-time setup*; without it, play with `-NoCapture`). Go, Visual Studio, Git's openssl and RakNet are not needed. Then:

```powershell
.venv\Scripts\python -I re\scripts\setup_all.py --player --server-host <S> --ca <path to ca_modulus.bin> [--client-bind <C>]
```

It extracts and checks the archive like the full setup, then makes the copy `client\run_854_lan\Dawngate` and patches it:

| Patch | Options | What changes |
|---|---|---|
| `patch_client.py` | `--profile lan --server-host <S>` and the CA file | The redirector host becomes `<S>`; the client finds Blaze, QoS, telemetry and the match host through it. EA's built-in "OTG3" certificate authority is replaced by the server's, and its "only `*.ea.com`" flag is cleared. UPnP stays off. The client's sockets bind all interfaces, as the shipped game did. Since Q3b the exe is also marked `LARGE_ADDRESS_AWARE` (4 GB of address space instead of 2 GB; the shipped client ran short of it in long matches). |
| | `--client-bind <C>` (optional) | The sockets bind only this machine's LAN address `<C>` instead of every interface (no VPN or other adapter gets them). |
| `patch_config.py` | `--host <S>` | The CDN, telemetry and crash-report hosts in the config packages point at `<S>`, and EAWebKit may open `<S>` (the main menu's home page). |

**The certificates.** The client accepts the server only if its certificate comes from the CA patched in (your `ca_modulus.bin`) and names exactly the address the client was patched for: its CN must be `<S>` (A5, read from the client's code). So use the address the operator made the certificates for. If the server's address or certificates change, get the new `ca_modulus.bin` and run the command again; it patches the copy anew from its untouched original. `<S>` and `<C>` must be private addresses of your own network: loopback, public and multicast addresses are refused. `setup_all.py --player --server-host <S> --ca <file> --check` says whether the copy is current.

**Starting it (since P2).** One command, the same as on one PC with the server's address added:

```powershell
powershell -ExecutionPolicy Bypass -File re\scripts\play.ps1 -Server <S>
```

It runs `re\scripts\play_lan.ps1` (you can also start that directly; without `-Server` it takes the address the copy was patched for). There is no server and no match host on your machine: the server's operator runs both. The script

1. checks the lan copy: it is there and patched (the exe and the config packages differ from their originals), patched for `<S>` (the lan profile's redirector host, the server's CA, the config packages naming `http://<S>:18080`), Python and, unless `-NoCapture`, Wireshark. For a gap it prints the `setup_all.py --player` command to run;
2. starts the game in a normal window (after about 5 seconds), with no time limit and nothing scripted, and records the session: a capture of 256 bytes per packet (the network adapter that reaches `<S>`, normally the one with the default route, and loopback) and the game's sockets;
3. ends the session when you **quit the game** (in the menus; in a match the close button doesn't work) **or press Ctrl+C** in the PowerShell window, which closes the game and stops it after 10 seconds in a match; a second Ctrl+C stops at once;
4. stops the capture and runs the **egress check** with `egress_report.py --allow-host <S>`: traffic between the game and `<S>` is expected, and a flow from the game to any other address, or anything EA-related, is flagged;
5. prints the summary (`summary.txt` in `re\logs\play_lan_<date>-<time>\`, with `application_log.txt`, `monitor.log`, `capture.pcapng` and `egress.txt`):

```
==== Dawngate session play_lan_20261010-200000 over: OK
  server  : 192.168.1.20
  session : ended when the game was closed at t=1810 s (code 0)
  egress  : 0 flagged line(s) (egress.txt)
  cleanup : no session process left
  logs    : <repo>\re\logs\play_lan_20261010-200000
            summary.txt; the client: application_log.txt; the server's logs are on the server machine
```

(an example: the format of the script's summary, not a recorded session). `egress` must say `0 flagged line(s)`; with `EGRESS FLAGGED` (exit code 1) something tried to talk to another machine: stop playing, keep the folder and report it. The server's own logs (the match, the host) stay on the server machine.

Options: `-NoCapture` (no capture, no egress check: a machine without Wireshark), `-KeepAlive` (as above: a key release every 60 seconds against the idle kick), `-Seconds N`, `-Name <folder>`, `-SetupOnly` (only the checks), `-AllowHost <H>[,<H2>]` (further machines of your network the game may talk to: when the operator runs match hosts on other machines, *Extra host machines* in [OPERATORS.md](OPERATORS.md), the game connects to that host machine for the match, so add its address; the summary's `app log` line names a match address the check doesn't allow). `play_lan.ps1` has two more: `-GameDir <Dawngate folder>` (a copy elsewhere, e.g. one made with `setup_all.py --player --client <folder>`) and `-DryRun` (the checks and what it would start, nothing started).

**One client at a time.** The copy keeps its log and options in `%APPDATA%\DawngateData` like the local copy and runs without `-multipleInstances`, so no other Dawngate client may run on the machine (the script says so). On the development PC it counts as the user's play session: it holds `re\logs\session.lock` (play mode), so other sessions on that PC wait for it, as for `play.ps1` (*Troubleshooting*). Windows Firewall asks about `Dawngate.exe` at its new path the first time it binds your LAN address (seen in A5b; in P2-live none was seen, cause unknown): the client only connects out, so cancelling worked for playing on the server's machine (the sessions there ran with the prompt unanswered); across machines it is untested.

**Before P2** this section started the copy with `launch_monitor.ps1 … -Seconds 0 -NoCapture` directly, without a capture (run directly, the monitor left its capture running after the game) and with `Stop-Process -Name Dawngate` to end a match; `play.ps1 -Server` replaces that, and the next start stops what such a run left behind from the same copy.

## The check mode

```powershell
powershell -ExecutionPolicy Bypass -File re\scripts\play.ps1 -Check [-Seconds 150]
```

`-Check` takes the same code path with a scripted login (a new account each time) and B8's clicks to PRACTICE DAWNGATE. It only posts window messages to the game, never using the cursor or keyboard, and keeps the window off the desktop (`-Background`). After `-Seconds` (default 150) the script closes the game the same way Ctrl+C does. The check passes (exit 0) when the client reached `kGameStateDungeon`, the host reported `gameReady`, egress has 0 flagged lines and the cleanup is clean. The exit code is 3 when the session was clean but the client didn't get into the game.

**How it works** (for changes to it): `play.ps1` is `run_session.ps1 -Play -GmsHost client\run_854_server` plus the setup checks. In play mode:

- the monitor runs with `-Seconds 0`: no time limit, no screenshots, and the capture keeps 256 bytes per packet with an 8-hour safety autostop;
- `run_session.ps1` stops the capture once the server is down, and `egress_report.py` reads a capture whose last packet was cut short;
- Ctrl+C arrives as a key (`[Console]::TreatControlCAsInput`);
- the session lock keeps play and test sessions apart.

**`play.ps1 -Server <S>` (P2)** is `re\scripts\play_lan.ps1`, which runs the same play mode without `run_session.ps1` (there is no server to build, start or stop): its own checks of the lan copy, `launch_monitor.ps1 -Seconds 0 -ShotTimes none -SnapLen 256`, the same Ctrl+C handling and game close, the capture stopped at the end, `egress_report.py --allow-host <S>`, the lock (`re\logs\session.lock` in play mode for `setup_all.py --player`'s copy; the development PC's lan test copy `client\run_854_l` takes `re\logs\session_lan.lock`) and the summary. `play_lan.ps1 -Check` is its check mode (the same login and clicks as `play.ps1 -Check`; it passes at `kGameStateDungeon` with a GMS address when the client is still in the match at the time limit, egress 0 flagged and a clean cleanup); `re\scripts\test_p2.ps1` tests it without a game (dry runs on scratch copies), and `test_p2.ps1 -Live -Lane <x>` is its live check on the development PC: a server on the PC's own LAN address with the lan test copy as the player.
